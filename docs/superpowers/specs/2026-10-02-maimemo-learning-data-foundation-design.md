# 墨墨学习数据基础设施设计

> 历史文档：本文保留 0.1.x 单镜像阶段的原始设计证据。当前命名与多包部署以
> `docs/superpowers/specs/2026-10-03-maimemo-project-naming-and-packaging-design.md` 为准；
> 升级步骤见 `docs/migration/maimemo-0.2.0.md`。

## 1. 文档状态

- 日期：2026-10-02
- 状态：已通过用户逐节确认
- 实施范围：第一阶段“学习数据基础设施”
- 后续阶段：词汇知识模型、Obsidian 投影、自适应学习智能体

## 2. 背景与目标

本项目通过墨墨开放 API 获取个人背词数据，在 NAS 上持续保存历史快照，并通过 MCP 向 ChatGPT 和其他智能体提供学习查询、薄弱词分析和个人混淆反馈能力。

第一阶段优先解决学习历史不可回溯的问题。系统必须从部署之日起持续采集可用数据，而不是等待词汇知识图谱完成后再开始记录。

第一阶段的成功标准是：用户能够通过自然语言可靠地查询今日学习情况、近期薄弱词、单词个人学习状态和数据健康度，并能把明确的易混反馈记录到本地数据库中。

## 3. 已确认约束

- 仅服务单个用户，使用用户自己的墨墨 Token。
- 部署在 NAS，通过 Docker Compose 运行。
- 使用 Python 和 PostgreSQL。
- ChatGPT 通过 Secure MCP Tunnel 访问私有 MCP 服务，不要求 NAS 暴露公网 MCP 地址。
- 墨墨开放 API 在第一阶段严格只读。
- 当前官方 OpenAPI 中所有语义上只读的操作必须接入 API Client，并提供对应 MCP 工具。
- 本地 PostgreSQL 允许受控的追加式反馈写入和撤销。
- 不实现墨墨侧添加单词、提前复习、创建或修改内容等写操作。
- 所有时间以 UTC 存储；每日统计和用户展示使用 `Asia/Shanghai`。
- 不把未知历史状态、系统候选易混词或 AI 生成内容表述成已经发生的个人事实。

## 4. 范围

### 4.1 第一阶段包含

1. 墨墨 API Client、认证、限流、重试和错误分类。
2. 当前全部 17 个只读操作的接入与 MCP 暴露。
3. 5 个面向学习目标的组合 MCP 工具。
4. 定时采集、原始响应留档、规范化历史和数据完整性标记。
5. 可解释、可版本化的薄弱词评分。
6. 用户确认和测验观测两类混淆反馈的本地事件模型。
7. 查询、追加反馈和撤销反馈的 MCP 工具。
8. OpenAPI 规范漂移检测。
9. 日志、健康检查、备份恢复和测试体系。

### 4.2 第一阶段不包含

- 任何墨墨侧写入操作。
- 完整词根词缀、语义演化、同反义词和考研语料知识图谱。
- Obsidian 文件生成或双向同步。
- 自动出题和完整自适应测验系统。
- 多用户、公开分发、OAuth 多租户授权。
- Neo4j、向量数据库、消息队列或拆分式微服务。
- 自定义 ChatGPT 图形界面。

## 5. 外部事实与限制

### 5.1 墨墨学习数据限制

当前学习数据接口处于公测状态，需要墨墨 App 开启自动同步。今日进度和今日单词可能在当天未打开 App 时不完整。

当前可用字段能够表达：

- 今日完成数、总数和学习时长；
- 今日单词、学习顺序、当天第一次反馈、新词状态和完成状态；
- 单词添加时间、首次学习时间、最近学习时间、下次学习时间；
- 最近一次反馈、每日计数口径的学习次数；
- `STICKING` 和 `WELL_FAMILIAR` 等标签。

当前 API 不提供完整的历次复习事件，也不直接提供“用户把 A 误认为 B”的混淆关系。因此系统只能从开始运行后积累自己的历史，不能伪造部署前的事件。

### 5.2 频控

当前官方限制为：

- 10 秒最多 20 次；
- 60 秒最多 40 次；
- 5 小时最多 2000 次。

所有 API 请求必须经过按 Token 共享的跨进程限流器。MCP 进程和 Worker 都可能调用官方 API，因此限流状态存放在 PostgreSQL 中，并使用数据库锁保证窗口计数一致。第一阶段只运行一个采集 Worker；采集任务仍须使用独立的任务锁避免重复调度。

### 5.3 OpenAPI 漂移

2026-10-02 获取的官方 OpenAPI 规范包含 38 个操作，而官方演示页曾描述 34 个操作。系统不得假设接口集合稳定。

构建过程保存所用规范的哈希，并定期比较官方规范：

- 新增只读操作：产生普通告警；
- 删除操作、修改路径或新增必填字段：产生高优先级告警；
- 新增可选响应字段：记录差异，不阻断采集。

## 6. 总体架构

项目采用一个 Python 代码库和一个应用镜像，以不同启动命令运行两个业务进程：

```text
ChatGPT / 其他智能体
          │
Secure MCP Tunnel
          │
          ▼
┌──────────────────────────────────────────────┐
│ NAS / Docker Compose                         │
│                                              │
│  maimemo-mcp                                 │
│  ├─ 原子只读工具                             │
│  ├─ 组合查询工具                             │
│  └─ 本地反馈追加与撤销                       │
│                                              │
│  maimemo-worker                              │
│  ├─ 定时调用墨墨只读 API                     │
│  ├─ 保存原始快照和规范化记录                 │
│  └─ 计算薄弱词指标                           │
│                                              │
│  tunnel-client                               │
│  └─ 将内部 MCP 端点连接到 ChatGPT            │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
                 PostgreSQL
```

Tunnel Client 的具体运行方式取决于实施时官方支持的发布形式。它可以作为 Compose 管理的进程，也可以作为 NAS 上受监督的独立进程；不得假设存在未经验证的官方 Docker 镜像。

MCP 进程与 Worker 分离，确保 Tunnel 或 MCP 重启不影响后台数据采集。两者使用同一代码库中的 API Client、存储模型和配置模块。

## 7. 代码边界

```text
src/
├─ maimemo_client/   # HTTP、认证、限流、重试、接口模型
├─ ingestion/        # 采集调度、快照、去重、规范化
├─ analysis/         # 薄弱词评分及解释生成
├─ feedback/         # 混淆反馈事件和撤销语义
├─ mcp_server/       # MCP 工具、Schema 和统一返回元信息
├─ storage/          # PostgreSQL 模型、迁移和查询
└─ settings/         # 配置、密钥路径和环境校验
```

每个模块通过明确接口通信。MCP Handler 不直接拼接 SQL，采集任务不直接生成面向模型的返回文本，评分模块不直接调用外部 API。

## 8. 墨墨只读 API 覆盖

只读性按业务语义判断，不能只看 HTTP 方法。下列 17 个操作全部接入：

### 8.1 墨墨记忆卡

1. `GET /api/v1/markji/decks/folders`：获取文件夹列表。
2. `GET /api/v1/markji/decks`：获取自建牌组列表。
3. `GET /api/v1/markji/decks/{deck}`：获取牌组信息。
4. `GET /api/v1/markji/decks/{deck}/chapters`：获取章节列表。
5. `GET /api/v1/markji/decks/{deck}/chapters/{chapter}`：获取指定章节。
6. `GET /api/v1/markji/decks/{deck}/cards/{card}`：获取指定卡片。
7. `POST /api/v1/markji/files/query`：查询文件。

### 8.2 墨墨背单词内容

8. `GET /api/v1/memo/interpretations`：获取释义。
9. `GET /api/v1/memo/notes`：获取助记。
10. `GET /api/v1/memo/notepads`：查询云词本。
11. `GET /api/v1/memo/notepads/{id}`：获取云词本详情。
12. `GET /api/v1/memo/phrases`：获取例句。

### 8.3 学习数据

13. `POST /api/v1/memo/study/get_study_progress`：获取今日进度。
14. `POST /api/v1/memo/study/get_today_items`：获取今日单词。
15. `POST /api/v1/memo/study/query_study_records`：查询学习记录。

### 8.4 单词

16. `GET /api/v1/memo/vocabulary`：获取单词。
17. `POST /api/v1/memo/vocabulary/query`：查询单词。

每个操作必须有独立 Client 方法、请求和响应模型、契约样例、异常测试以及对应原子 MCP 工具。

## 9. MCP 工具设计

### 9.1 原子工具

原子工具保持与只读操作一一对应：

- `list_markji_folders`
- `list_markji_decks`
- `get_markji_deck`
- `list_markji_chapters`
- `get_markji_chapter`
- `get_markji_card`
- `query_markji_files`
- `get_interpretations`
- `get_notes`
- `list_notepads`
- `get_notepad`
- `get_phrases`
- `get_study_progress`
- `get_today_items`
- `query_study_records`
- `get_vocabulary`
- `query_vocabulary`

这些工具标记 `readOnlyHint = true`，描述中明确输入限制、返回来源和适用场景。

### 9.2 组合工具

- `get_daily_study_dashboard`：今日进度、今日单词和薄弱项摘要。
- `get_word_learning_profile`：单词内容、个人学习记录和薄弱因素。
- `get_weak_words`：按时间范围、阈值和数量返回薄弱词。
- `get_due_review_overview`：汇总未来复习压力。
- `get_learning_data_health`：返回同步新鲜度、缺失日期和采集异常。

组合工具使用内部服务层，不通过 MCP 再调用原子工具。

### 9.3 本地反馈工具

- `record_confusion_feedback`：追加一条明确的反馈事件。
- `retract_feedback`：追加撤销事件，不物理删除原事件。

明确的用户陈述可以直接记录。系统推测必须先获得用户确认。测验错误记录为 `QUIZ_OBSERVED`，不得标记成 `USER_CONFIRMED`。

### 9.4 统一返回结构

所有工具返回稳定的数据包：

```json
{
  "data": {},
  "meta": {
    "source": ["maimemo_api", "local_history"],
    "fetched_at": "2026-10-02T14:30:00Z",
    "data_through": "2026-10-02",
    "completeness": "complete",
    "warnings": []
  }
}
```

`completeness` 至少支持 `complete`、`partial`、`stale` 和 `unavailable`。MCP 文本摘要不得掩盖结构化结果中的警告。

### 9.5 实时调用与历史数据边界

为了同时满足“全部只读 API 均可通过 MCP 调用”和“后台历史不被对话请求污染”，工具分为两种数据路径：

- 17 个原子工具按需实时调用对应的墨墨只读 API，返回本次实时结果；
- 组合学习工具优先使用 PostgreSQL 中的历史、评分和最近一次有效快照；需要实时内容时由内部服务直接调用 API，并在元信息中区分实时与历史来源。

对话触发的实时调用不写入 `daily_word_observation`、`study_record_snapshot` 或 `weakness_score`，也不改变 Worker 的采集计划。它可以记录脱敏的调用指标，但默认不持久化完整响应。只有 Worker 采集产生正式历史快照。

因此，原子工具中的“只读”同时表示：不修改墨墨数据，也不制造个人学习历史。用户明确调用本地反馈工具时产生的追加事件是单独、可追溯的本地写入。

## 10. 采集策略

- 每 30 分钟采集今日进度和今日单词。
- 每 2 小时刷新学习记录和复习计划。
- 每天结束后生成当日汇总。
- Worker 启动后补做一次采集。
- 相同响应通过稳定内容哈希去重。
- 所有任务使用 `Asia/Shanghai` 判断学习日，数据库时间字段使用 `timestamptz`。

采集频率在配置中可调整，但默认值必须受测试约束。调度不得在多个 Worker 实例中重复运行；第一阶段使用 PostgreSQL Advisory Lock 或等效数据库锁保证单实例执行。

## 11. 数据模型

### 11.1 采集与内容

`vocabulary`

- 墨墨单词 ID；
- 规范化拼写；
- 原始拼写；
- 首次发现时间；
- 最近发现时间。

`ingestion_run`

- 任务类型；
- 开始和结束时间；
- 状态；
- 请求数量和结果数量；
- 错误类别和脱敏错误摘要。

`api_snapshot`

- 接口标识；
- 请求参数哈希；
- 响应内容哈希；
- 原始响应 `JSONB`；
- 获取时间；
- 对应采集任务。

`api_rate_limit_window`

- Token 的不可逆标识哈希；
- 限流窗口类型和窗口起点；
- 已使用请求数；
- 最近更新时间。

该表只用于 MCP 和 Worker 的共享限流，不保存 Token 本身。

### 11.2 学习历史

`daily_progress`

- 学习日；
- 已完成数、总数、学习时长；
- 完整性状态；
- 首次和最近观测时间。

`daily_word_observation`

- 学习日和单词；
- 当天第一次反馈；

- 是否完成；
- 首次和最近观测时间；
- 来源快照。

`study_record_snapshot`

- 单词；
- 观测时间；
- 添加、首次学习、最近学习和下次学习时间；
- 最近反馈；
- 学习次数；
- 标签；
- 来源快照。

### 11.3 分析结果

`weakness_score`

- 单词；
- 计算时间；
- 算法版本；
- 总分；
- 风险等级；
- 置信度；
- 各评分因子 `JSONB`；
- 证据起止时间；
- 使用的最新快照。

### 11.4 反馈事件

`learning_feedback_event`

- 事件 ID；
- 事件类型；
- 两端单词或未解析拼写；
- 关系类型；
- 方向；
- 证据类型；
- 用户备注；
- 来源智能体和可选会话引用；
- 幂等键；
- 创建时间；
- 被撤销事件 ID。

单词无法从墨墨词库解析时允许保存为 `UNRESOLVED`，不得生成虚假墨墨 ID。

## 12. 薄弱词评分

第一版输出 0 到 100 的分数，并同时输出风险等级、置信度和自然语言可解释原因。

初始因子权重：

- 35%：近期反馈，`FORGET` 高于 `VAGUE`，并随时间衰减；
- 25%：有效观测日中的反复失误率；
- 15%：`STICKING` 等顽固状态；
- 15%：复习间隔持续较短或已经逾期；
- 10%：多次进入当日列表后仍未完成。

评分规则：

- 新词单独标记，避免天然高危；
- 学习次数必须结合加入时长和失误率，不直接等同难度；
- 一次偶发忘记只提高近期风险；
- 连续认识后分数缓慢下降；
- 缺失因子跳过并降低置信度，不按零分处理；
- 算法使用明确版本，例如 `weakness-v1`；
- 权重属于初始假设，至少积累两周数据后再基于实际分布评估，不得静默修改。

## 13. 混淆关系证据

薄弱和混淆是两个独立概念。关系类型至少包括：

- `FORM_SIMILAR`
- `SOUND_SIMILAR`
- `MEANING_OVERLAP`
- `USAGE_CONTRAST`
- `USER_CONFIRMED`
- `QUIZ_OBSERVED`

证据强度从高到低为：

1. 用户明确确认；
2. 项目内测验记录到具体错误答案；
3. 两词反复在相近时间共同出错；
4. 系统根据形式、发音、词义或用法生成候选。

第三、第四类不能被描述成“用户经常搞混”。混淆具有方向性，`A → B` 不自动推出 `B → A`。

## 14. 数据缺失与一致性

- 首次同步数据标记为 `BASELINE`，不得反推部署前的历史事件。
- API 返回空结果时，先根据接口语义判断是有效空集还是同步缺失。
- 同步失败不得用空值覆盖最近有效状态。
- 当日未打开 App、自动同步未完成或公测接口异常时标记 `INCOMPLETE`。
- 每个结论返回数据截止时间和完整性。
- 采集事务按“原始快照、规范化数据、分析结果”原子提交；失败则回滚。
- `ingestion_run` 的失败记录使用独立短事务保存，保证主事务回滚后仍可诊断。

## 15. API 错误处理

- `429`：优先遵循服务端等待时间，否则指数退避并加入随机抖动。
- `5xx`、连接重置和超时：有限次数重试。
- `401/403`：不重试，标记认证失效并产生告警。
- 请求校验错误：不重试，返回可操作的参数错误。
- 缺少必填响应字段：保存原始响应，拒绝规范化，不覆盖旧数据。
- 未知可选字段：保留在原始 `JSONB`，不导致失败。
- PostgreSQL 不可用：采集失败，不以内存状态冒充已持久化成功。
- Tunnel 断开：不影响 Worker；MCP 恢复后继续读取已有数据。

## 16. 安全

- Token 使用 Docker Secret 或只读密钥文件注入。
- Token 不进入镜像层、数据库、日志、异常正文或 MCP 结果。
- PostgreSQL 使用独立最小权限账号。
- MCP 端口默认不映射到公网。
- 所有输入限制类型、长度、枚举、分页和最大数量。
- 不提供任意 HTTP 转发、任意 SQL、任意文件读取或物理删除工具。
- 日志只记录接口、耗时、状态码、追踪 ID 和脱敏错误类别。
- 反馈写入记录来源、时间和幂等键，并支持撤销。
- 跨进程限流仅使用 Token 的不可逆标识哈希，不得把 Token 原文写入 PostgreSQL。

## 17. 可观察性与运维

至少提供：

- 进程存活和就绪检查；
- 最近一次成功采集时间；
- 各任务连续失败次数；
- API 状态码和延迟分布；
- 限流等待次数；
- 数据库迁移版本；
- OpenAPI 规范哈希和漂移状态；
- Tunnel 独立健康状态。

原始学习数据第一阶段长期保留。清理策略必须在观察实际数据规模后另行设计，不能默认删除。数据库纳入现有 PostgreSQL 备份，并定期执行空库恢复演练。

## 18. 测试策略

### 18.1 单元测试

- API 响应规范化；
- 时间和学习日边界；
- 内容哈希和幂等；
- 薄弱词各因子、衰减、新词校正和缺失数据；
- 反馈方向、证据类型、重复写入和撤销。

### 18.2 契约测试

- 17 个只读接口各有脱敏成功样例；
- 覆盖空结果、非法参数、认证失败、限流和服务错误；
- 验证未知可选字段兼容和缺少必填字段失败；
- 比较官方 OpenAPI 操作集合和关键 Schema。

### 18.3 PostgreSQL 集成测试

- 迁移和回滚；
- 事务一致性；
- 快照去重；
- Advisory Lock；
- 时间范围查询；
- 备份恢复后的关键数据一致性。

### 18.4 MCP 测试

- 使用 MCP Inspector 枚举和调用全部工具；
- 验证输入、输出 Schema 和安全标注；
- 验证统一元信息；
- 验证墨墨写操作不存在；
- 验证反馈工具不能越权修改其他数据。

### 18.5 对话评测

- 直接工具请求；
- 相同意图的间接表达；
- 多轮追问并复用标识符；
- 数据缺失和过期；
- 明确混淆反馈；
- 推测性混淆不自动写入；
- 错误反馈撤销；
- 要求墨墨写入时明确拒绝或说明未支持。

### 18.6 真实接口冒烟测试

只调用墨墨只读操作。真实 Token 和完整个人响应不得进入测试报告或 CI 日志。

## 19. 验收标准

第一阶段只有在下列条件全部满足后才算完成：

1. 当前 17 个只读操作均有 Client、原子 MCP 工具和契约测试。
2. 5 个组合工具能返回稳定结构和统一元信息。
3. Worker 按计划采集，重复响应不产生重复历史。
4. 系统能返回薄弱词、评分原因、置信度和数据截止时间。
5. 系统能记录和撤销个人混淆反馈。
6. 墨墨写操作未注册到 MCP。
7. Token 未出现在镜像、日志、数据库和工具结果中。
8. 数据缺失、认证失败、限流和接口漂移都有可观察状态。
9. PostgreSQL 备份能在空库中恢复，并通过关键一致性检查。
10. ChatGPT 能通过 Secure MCP Tunnel 完成代表性对话评测。

## 20. 后续路线

### 阶段二：词汇知识模型

建立词元、词形、义项、词性、词素、搭配、句型、例句、关系和证据模型。词形变化、词族派生、多义词扩展和个人混淆必须分别建模。个人规模先使用 PostgreSQL 关系表和递归查询，不引入图数据库。

### 阶段三：Obsidian 投影

PostgreSQL 作为结构化事实来源，Obsidian 作为阅读和人工补充界面。自动生成区域与“我的笔记”分开，更新不得覆盖人工内容；词条之间使用稳定 WikiLink。

### 阶段四：自适应学习智能体

根据薄弱词生成练习，记录具体错误答案，识别方向性混淆，并把测验证据反馈给薄弱模型。考研真题必须来自可核验语料；AI 生成句子必须明确标记为生成内容。
